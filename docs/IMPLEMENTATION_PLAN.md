# 五单元轻量实施路线与状态

## 1. 全局目标

以单一 Next.js 全栈应用和 PostgreSQL 为基础，逐单元交付可运行、可验证的智慧农业职场闯关沙盘。学生成长档案和教师看板从第一单元起持续读取统一数据，但在五个单元主线全部完成后再进行完整化验收；Excel 导入、正式报告和校内试点均排在五单元之后。

## 2. 技术与系统边界

- 页面、Route Handler 与领域服务保留在同一 Next.js 工程；不预设独立后端、Redis、MinIO 或 WebSocket。
- PostgreSQL 是唯一业务数据库，Prisma 管理用户、班级、单元、任务、互动、尝试、进度、事件和能力快照。
- 普通互动使用 React 状态和纯函数；仅对确有复杂分支、恢复或跨步骤约束的任务按需采用 XState。
- 学习事件服务于进度、档案和看板，不建设完整事件溯源、评分账本或投影回放。
- 农小智首版使用确定性脚本和规则反馈；AI 自由对话及知识检索后置。
- 图片和透明 PNG 位于 `public/assets/`；编号、提示词、规格、版本、状态和复用范围维护在 `docs/assets/` 与单元素材文档。
- 小组任务首选共享设备、组长提交或异步汇总，不默认实时多人协作。
- 普通互动完成后保持原场景与操作结果可见，以页面内模态层提供“继续下一项”和“返回单元地图”；不设置独立得分页，也不在逐互动完成反馈中展示分数。统一数据层仍保留完成状态、过程证据和内部评分字段供档案与授权汇总使用。

## 5. 第二至第五单元范围与状态

### M1 第二单元：认识自我 健康成长

- 高层目标：帮助学生识别兴趣、性格、能力与压力反应，形成不贴标签、可行动的自我认识。
- 主要内容：自我探索任务、情绪与挫折情境、心理韧性练习、阶段性成长反馈。
- 前置条件：第一单元首版稳定；复核心理安全、隐私字段和教师可见范围；完成本单元四份门禁文档。
- 验收标准：核心情境和分支完整；反馈不诊断疾病、不公开敏感回答；能力变化和数据来源可解释。
- 执行结果：已完成 21 个编号交互（15 主线、6 支线）、6 张场景背景、5 件透明装置、6 张表情教学图和四份单元规格；学生成长档案展示第二单元进度、心理韧性与策略，教师看板仅展示聚合完成率、能力变化和策略分布。
- 验证结果：lint、typecheck、12 个单元测试、8 个核心 E2E、生产构建和 48 项素材覆盖检查通过；桌面与 Pixel 5 截图已归档。
- 2026-07-27 交互修复：情绪调节舱单项体验改为 10 秒，并修复装饰光环拦截按钮点击；团队角色认领加入五类矢量图标和加大字号。

### M2 第三单元：和谐交往 快乐生活

- 高层目标：训练真实职场中的表达、倾听、协作、冲突处理和关系边界。
- 主要内容：沟通情境、协作任务、矛盾调解、团队复盘和个人行动建议。
- 前置条件：确定共享设备、异步汇总或组长提交模式；定义小组数据归属；完成本单元四份门禁文档。
- 验收标准：协作过程不是普通选择题；个人与小组贡献边界清楚；教师汇总避免公开排名和负向标签。
- 执行结果：已完成 20 个编号交互（14 主线、6 支线），覆盖主管汇报、团队协调、客户投诉、丰收节共享设备协作、三类矛盾调解、感恩表达、关系花园和共情剧场；全部接入统一 Attempt、Progress 和 LearningEvent。
- 视觉与素材：完成 6 张主场景、露天舞台/室内仓库 2 张分歧对比场景、3 组透明角色素材和 3 套案件分镜（页面派生为 9 张独立镜头）；复杂协作、拖旗授旗、角色视角、动态卡片、关系生长与和谐之门均保留过程互动，没有降级为静态题卡。
- 验证结果：lint、typecheck、14 个单元测试、9 个核心 E2E、生产构建和 64 项素材覆盖检查通过；桌面与移动端截图已归档。
- 2026-07-27 交互修复：队长选举增加任务旗图标与拖放；意见分歧加入两张实景方案图；Case #001 增加三镜头说明和三种独立视角题，Case #002 使用横排独立镜头并按真实比例适配移动端。

### M3 第四单元：学会学习 终身受益

- 高层目标：建立学习策略、信息判断、数字工具使用和持续更新岗位技能的能力。
- 主要内容：学习方法选择、信息检索与判断、数字工具实践、岗位技能更新计划。
- 前置条件：盘点视频、外部工具和 AI 依赖，明确无素材时的可见状态；完成本单元四份门禁文档。
- 验收标准：学习操作有过程证据；外部依赖失败不伪装成功；学习力指标可由真实行为解释。

- 验证结果：lint、typecheck、16 个单元测试、10 个核心 E2E、生产构建和 75 项素材覆盖检查通过；桌面与 Pixel 5 视觉截图已归档。

## 6. 单元开发门禁

第二至第五单元在正式开发前必须分别创建并评审：

1. `UNIT_SPEC.md`：全部任务、交互流程、分支、完成条件与数据采集。
2. `ANIMATION_SPEC.md`：场景、视觉、动画、转场、反馈、降低动态模式和技术实现层。
3. `ASSET_MANIFEST.md`：素材编号、用途、规格、路径、版本、状态和复用范围。
4. `ASSET_PROMPTS.md`：最终生成提示词、负面约束、生成方式和保存位置。

四份文档通过后才进入素材生成和实现；可复用角色、设备、特效和 UI 必须先登记到全局素材库。

## 7. 持续质量门禁

- 每个批次至少通过 lint、typecheck、相关单元测试、核心 E2E 和生产构建。
- 动态场景、拖拽、滑杆、路径动画、反馈和分支不得降级为静态卡片或普通选择题。
- 所有互动必须更新 Attempt、Progress 和统一学习事件，学生端与教师端不得使用硬编码演示图表。
- 互动完成反馈必须覆盖在原页面上，不显示逐互动得分，并同时提供继续下一项和返回单元地图入口。
- 缺失授权视频、配音或外部内容时显示明确状态并登记清单，不以虚假素材替代。
- 性能、并发、全量视觉回归与备份恢复集中在 M7 专项执行。
