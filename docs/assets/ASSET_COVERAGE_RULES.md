# 视觉素材覆盖与勾稽规则

适用范围：第一至第五单元、系统首页、成长档案、教师看板。本文是页面进入实现和验收的强制门禁，不以页面“能显示”替代视觉需求覆盖。

## 1. 统一分类

每个“任务 → 交互点 → 视觉对象”只能选择一种主实现方式：

| 标记 | 含义 | 适用对象 |
|---|---|---|
| `CODE` | CSS、SVG、Canvas、WebGL、DOM 或图表库实时生成 | 粒子、路径、流光、图表、按钮、文字、连续参数反馈 |
| `GLOBAL` | 引用全局素材库 | 农小智、五职业角色、可跨单元设备、通用道具和徽章底板 |
| `UNIT` | 新生成的单元专属素材 | 单元场景、时代农具、单元专属装置和徽章图案 |
| `EXTERNAL` | 由校方或权利人提供 | 真人肖像、纪实视频、校本标识和受限媒体 |

具有稳定且需要辨识的外观的角色、复杂机器、设备、农产品和教学观察样本，不得仅用通用图标或几何方块代替。会随操作、数据或状态连续变化的效果优先用代码实现，不得为了补数把扫描线、波形、喷洒轨迹、按钮或图表固化为位图。

## 2. 单元开发五道门禁

### G0 视觉需求台账

正式开发前，`UNIT_SPEC.md` 和 `ANIMATION_SPEC.md` 中每个交互点必须在 `ASSET_MANIFEST.md` 或审计附表中逐项出现，并记录：需求原文、视觉对象、实现方式、素材编号、状态和验收方式。缺一项不得进入素材规划。

### G1 先登记后生成

所有 `GLOBAL`、`UNIT` 和 `EXTERNAL` 项必须先分配稳定素材编号、路径、规格、版本、复用范围和状态，再写入完整提示词或外部来源要求。状态至少经历：

`planned` → `prompt-ready` → `generated` → `cleaned` → `approved`

外部素材使用 `blocked-external`；代码效果使用 `implemented-code`。没有 `prompt-ready` 记录不得调用生成工具，没有全局复用判断不得在单元目录另做一份。

### G2 文件与质量勾稽

生成后必须在同一工作批次更新素材清单和提示词文档，记录生成方式、源文件、成品路径、实际尺寸/格式、版本、QA 报告和日期。透明 PNG 必须检查 alpha 通道、四角透明、白底、深底和棋盘格；场景图必须检查文字、水印、假 UI、16:9 构图和交互留白。

### G3 代码引用勾稽

页面实现前必须满足：

- 每个代码引用的 `/assets/...` 文件实际存在，并能按路径反查唯一素材编号；
- 每个状态为 `approved` 的文件实际存在；
- `public/assets/` 中不存在未登记文件；
- 全局素材通过统一映射引用，禁止在单元内复制同一外观；
- `blocked-external` 必须在界面和文档中保留明确占位/阻塞说明，不得静默伪造。

### G4 页面视觉覆盖复核

页面完成后按“任务 → 交互点”重新对照 `UNIT_SPEC.md`、`ANIMATION_SPEC.md` 和素材清单逐项勾选。至少检查默认、操作中、成功、失败/重试、窄屏和 `prefers-reduced-motion` 状态；关键场景保留截图。页面能打开、卡片能显示或自动化测试通过，都不能单独作为视觉完成依据。

## 3. 必填覆盖表

每个单元使用以下字段，不得以素材族的一行 `approved` 覆盖多个尚未核对的对象：

| 字段 | 要求 |
|---|---|
| 任务/交互点 ID | 与 `UNIT_SPEC.md` 一致 |
| 需求来源 | 文档章节或原始需求位置 |
| 视觉对象 | 背景、角色、道具、装置、图标/徽章、插画或代码特效 |
| 实现方式 | `CODE` / `GLOBAL` / `UNIT` / `EXTERNAL` |
| 素材编号/代码位置 | 精确到编号或模块 |
| 状态 | 使用统一状态词 |
| 页面引用 | 实际路由或组件 |
| QA | 文件 QA、交互 QA、截图和问题编号 |

## 4. 变更同步规则

1. 视觉需求变化时，先改规格和覆盖表，再改提示词、素材和代码。
2. 生成或接收文件时，同步更新清单、提示词/来源、复用矩阵和 QA；禁止事后批量补记。
3. 路径、版本或状态改变时，必须同时搜索并修正代码引用与两级清单。
4. 素材废弃使用 `deprecated` 并记录替代编号；不得直接删除记录造成断链。
5. 新单元只能复用已登记的全局素材；需要外观变体时创建全局变体编号并说明差异。

## 5. 各单元可复用流程

第二至第五单元正式开发前依次完成：

1. 补齐该单元 `UNIT_SPEC.md` 与 `ANIMATION_SPEC.md`。
2. 建立逐交互视觉覆盖表并完成 `CODE/GLOBAL/UNIT/EXTERNAL` 判定。
3. 更新全局复用矩阵，完成 `ASSET_MANIFEST.md` 与 `ASSET_PROMPTS.md`。
4. 通过 G0/G1 后生成素材，通过 G2 后进入页面实现。
5. 页面接入统一事件模型，并通过 G3/G4、lint、typecheck、关键测试和 build。

任何交互点未完成覆盖检查时，该交互点不得标为开发完成；任何单元未完成 G4 时，不得标为视觉验收通过。
